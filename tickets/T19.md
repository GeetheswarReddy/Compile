# Ticket T19: Build the question-left, editor-right practice workspace

Priority: P1
Status: Ready after dependencies
Depends on: T17, T18

## Requested layout

On desktop, the question occupies the upper-left pane, Demo Trace the lower-left pane, and the Python editor the right pane with its action bar and results beneath it. This is explicitly requested by the user. The repository screenshot is evidence of current problems, not a screenshot of the target layout.

```text
+-----------------------------------------------------------+
| Compile / topic / progress                      navigation |
+---------------------------+-------------------------------+
| Question                  | Python editor                 |
| Prompt, examples,         |                               |
| constraints, hints        |                               |
+---------------------------+-------------------------------+
| Demo Trace                | Run & Check   next / generate |
| Provenance / retries /    +-------------------------------+
| mastery                   | Result                        |
+---------------------------+-------------------------------+
```

## Work and acceptance criteria

- At 1440×900 and 1280×720, question and editor are side by side, approximately 45/55 width; trace is visibly anchored below the question, never below the entire editor/page.
- Use available viewport height under compact navigation. Question, trace, editor, and results can scroll independently where needed; the primary execution control stays reachable.
- Question pane includes prompt, public examples, constraints when supplied, difficulty, provenance, and user-requested hints. Preserve technique reveal behavior and keep solutions hidden until requested.
- Trace shows existing provenance, retries, and mastery data, refreshes for relevant question/attempt changes, and has compact loading/empty/error states. When its flag is false, no trace is rendered or fetched and the question pane uses the freed space.
- Place hints in the left question/support region; reflection and history remain accessible through secondary sections without pushing trace or editor out of view. Preserve correct active-question binding and recording eligibility.
- Results display beneath the editor: pass/fail, available diagnostics, and no more than the permitted failed cases. Keep Run & Check as the single practice execution action.
- Apply the same question-left/editor-right arrangement to baseline with progress and its existing submit behavior; baseline does not invent practice trace events.
- Below 900px, stack question, editor/actions/results, then trace/support in a usable reading order. At 390px no horizontal page overflow or inaccessible controls.
- Keyboard navigation and landmarks follow a sensible order. Do not add mouse-only resizing; pane resizing is optional and not required for this ticket.
- Visual screenshots at all specified sizes plus mounted tests verify placement, trace flag, completion, loading/error, and quota states. DOM tests alone do not establish layout correctness.
